# Chrome Inspector Suite

Ten small Chrome extensions (Manifest V3) that inspect the page you are looking
at. Each one does a single job, runs entirely in your browser, and ships with no
backend, no analytics and no build step.

| Extension | What it does |
|-----------|--------------|
| [SEO Inspector](extensions/seo-inspector) | On-page SEO, Open Graph and accessibility audit with a verdict per check. |
| [Tracking Inspector](extensions/tracking-inspector) | Lists the analytics and advertising tags a page loads, with their IDs. |
| [Shopify Store Inspector](extensions/shopify-store-inspector) | Theme, currency, product and app details of any Shopify storefront. |
| [Schema Inspector](extensions/schema-inspector) | Parses JSON-LD and Microdata and checks the properties each type requires. |
| [Image ALT Inspector](extensions/image-alt-inspector) | Every image on the page with its alt text judged, and a CSV export. |
| [DataLayer Viewer](extensions/datalayer-viewer) | Browse `window.dataLayer` as a tree, with its events and GTM containers. |
| [Link Extractor](extensions/link-extractor) | Extract, filter and export every link on the page as CSV. |
| [Page to Markdown](extensions/page-to-markdown) | Turn the readable part of a page into clean Markdown. |
| [Table to CSV](extensions/table-to-csv) | Convert any HTML table to CSV, colspan and rowspan included. |
| [Tech Stack Detector](extensions/tech-stack-detector) | Identify the frameworks, CMS and libraries behind a page. |

---

## Install one

Each folder under `extensions/` is a complete, independent extension.

1. Open `chrome://extensions` in Chrome.
2. Turn on **Developer mode**.
3. Click **Load unpacked**.
4. Select the extension's folder - the one containing `manifest.json`.

No build step. The folder *is* the extension.

## Permissions

Every extension in this suite declares exactly three permissions and nothing else:

| Permission  | Why |
|-------------|-----|
| `activeTab` | Grants access to the current tab **only at the moment you click the icon**, and only until you navigate away. This is why none of these extensions needs `host_permissions`, and why none of them can see your browsing history. |
| `scripting` | Required to run the read-only collector in the page. |
| `storage`   | Holds a Pro license key on your own device. Nothing else is stored, and it never leaves the machine. |

No background service worker, no `tabs`, no host permissions.

### Privacy

Each extension reads the page you explicitly ask it to inspect, keeps the result
in the popup's memory, and forgets it when the popup closes. Nothing is written
to disk unless *you* click an export button, and nothing is transmitted.

Two things are worth stating plainly rather than burying:

- **Tracking Inspector reads cookie names, never cookie values.** A name tells
  you a tracker is present; the value is the identifier itself.
- **SEO Inspector renders `og:image` in its social preview card**, which fetches
  that image from wherever the page already hosts it, with
  `referrerpolicy="no-referrer"`. That is the only outbound request anything in
  this repository makes, and it is the same request the page itself would make.

## How the code is organised

```
shared/                  Single source of truth for code used by every extension
  page.js                Tab access and the "this page is off-limits" explanations
  ui.js                  DOM helpers - no framework, no innerHTML
  output.js              Copy, download, CSV writing
  entitlements.js        Licence parsing, verification and the feature catalogue
  license-ui.js          The Pro gate: badge, upgrade panel, key entry
  license-key.js         Generated public key (safe to ship)
  popup.css              The design system, light and dark

extensions/<name>/
  manifest.json          Generated from tools/extensions.mjs
  icons/                 Generated by tools/make-icons.mjs
  src/
    popup/
      popup.html         Popup markup - no inline script, per the MV3 CSP
      popup.js           Orchestration: read tab, apply rules, render, export
      base.css           Copy of shared/popup.css - do not edit
      theme.css          Accent colour, plus any bespoke component
    content/
      collect.js         Self-contained DOM reader, injected into the page
    shared/              Copies of shared/*.js - do not edit
    lib/
      <rules>.js         Pure logic: data in, decisions out   (tested)
  test/                  Unit tests for the pure logic
  README.md              Generated by tools/make-readmes.mjs

test/                    Tests for the shared code
tools/                   Registry, generators and the consistency checker
```

### The split that matters

Every extension follows the same three-way separation:

- **`content/collect.js`** touches the DOM but makes no judgements. It gathers
  raw facts and returns plain objects.
- **`lib/*.js`** makes every judgement but never touches the DOM. Pure functions,
  which is why they can be unit-tested under plain Node with no browser mocks.
- **`popup.js`** only wires the two together and renders.

Changing a threshold, a rule or a detection means editing one pure module with
tests around it.

### Why code is copied rather than imported

An extension loaded with "Load unpacked" cannot import from outside its own
folder. So `shared/` is the source of truth and `tools/sync-shared.mjs` copies it
into each extension. **Never edit `src/shared/` or `src/popup/base.css`** - edit
`shared/` and run `npm run sync`. `npm test` fails if any copy is stale.

### Injected collectors

`content/collect.js` is serialised with `Function.prototype.toString()` and
injected by `chrome.scripting.executeScript()`. It must be entirely
self-contained: no imports, no references to module scope. `npm run check`
enforces this.

Four extensions inject into the **MAIN world** (`world: 'MAIN'`), because the
data they need - `window.dataLayer`, `window.Shopify`, `window.fbq`,
`window.React` - belongs to the page and is invisible from the isolated world a
content script normally runs in.

## Development

Requires Node 21 or newer, only for the tests and the generators. The extensions
themselves have zero dependencies.

```bash
npm test
```

385 tests cover the pure logic of all ten extensions plus the shared code. They
run under plain Node: no DOM, no browser mocks, no test framework.

| Command | What it does |
|---------|--------------|
| `npm test` | Checks shared copies are in sync, then runs every test |
| `npm run check` | Static checks across all ten extensions (see below) |
| `npm run sync` | Copies `shared/` into every extension |
| `npm run icons` | Regenerates every icon from code |
| `node tools/scaffold.mjs` | Regenerates manifests and theme accents |
| `node tools/make-readmes.mjs` | Regenerates the per-extension READMEs |
| `npm run listings` | Regenerates the Chrome Web Store listings |
| `npm run package` | Tests, checks, then builds the upload zips into `dist/` |
| `npm run release` | Regenerates everything, then packages |
| `node tools/import-logo.mjs <slug> <logo.png>` | Turns a designed PNG into the four icon sizes |
| `node tools/fit-screenshot.mjs <slug> <shot.png>` | Fits a screenshot to the store's 1280x800 |
| `node tools/make-keypair.mjs` | Creates the licensing key pair (once, ever) |
| `node tools/make-license.mjs --email x@y.z` | Signs a Pro license key |

### What `npm run check` verifies

Unit tests cannot see a typo in an element id or a class with no CSS rule, so
these are checked statically for every extension:

- The manifest is valid MV3 and every file it points at exists
- The Web Store description fits in 132 characters
- No permission beyond `activeTab`, `scripting` and `storage`
- Every `getElementById` target exists in the popup markup
- Every CSS class used by markup or script has a rule
- No inline `<script>`, which the MV3 CSP would block
- `popup.js` loads as a module and every import resolves
- Injected collectors are self-contained

### Adding an extension

1. Add an entry to `tools/extensions.mjs`.
2. Run `node tools/scaffold.mjs` and `npm run icons`.
3. Write `src/content/collect.js`, `src/lib/*.js`, `src/popup/*` and `test/*`.
4. Add its README content to `tools/make-readmes.mjs`.
5. Run `npm run sync && npm run check && npm test`.

## Icons

The icons are placeholders, drawn from code by `tools/make-icons.mjs` using only
Node built-ins - so the repository carries no binary blobs it cannot regenerate
and no image dependency.

To ship a designed logo instead, save it as a square PNG and run:

```bash
node tools/import-logo.mjs shopify-store-inspector ~/Downloads/logo.png
```

That decodes, resizes with a box filter and writes all four sizes in place - no
image dependency, and nothing references the generator at runtime.

## Publishing

Every extension carries a `STORE-LISTING.md`: the name, both descriptions, the
category, the privacy answers, the permission justifications and a screenshot
plan - each in the order the submission form asks for it. Generated by
`tools/make-listings.mjs` from `tools/listings.mjs`, so it is regenerable.

To build the uploads:

```bash
npm run package
```

That runs the tests and the consistency checks first, then writes
`dist/<slug>-<version>.zip` for all ten. Each zip contains `manifest.json`,
`icons/` and `src/` and nothing else - tests, READMEs and listing notes only
slow a review down.

Then, per extension: upload the zip at the
[developer console](https://chrome.google.com/webstore/devconsole) and paste
each block from its `STORE-LISTING.md` into the field it names.

The one thing not generated is the screenshots. They have to be taken from a
running Chrome, and they are the single biggest factor in whether a visitor
installs - the shot list in each listing says exactly what to capture.

Capture them however you like, then let the fitter handle the size the store
demands:

```bash
node tools/fit-screenshot.mjs shopify-store-inspector ~/Desktop/shot1.png
```

It scales to fit - never crops - and centres the result on a dark tint of the
extension's accent, into `store-assets/<slug>/`.

None of these extensions contains remote code, external dependencies or data
collection, so the Web Store privacy form is answered with "does not collect
user data" throughout.
